## Decisions and Rationale

1. **ESLint 8 + `.eslintrc.json`**: Retained ESLint 8 and legacy config format rather than migrating to ESLint 9 flat config, ensuring full native compatibility with Next.js 14's `next lint`.
2. **`module` Removal vs `type` Retention**: `"module"` was dead metadata for an App Router web app, while `"type": "module"` is required by Next.js ESM configuration.
3. **Simulated State on Monitor Page**: Provided realistic testing surfaces (outage simulation, connect delay) while keeping all data local and non-destructive.
4. **Minimal Dead Link Correction**: Restructured only demonstrably broken link (`ProjectCard.tsx`) without altering working navigation paradigms.

## Known Limitations

1. **Pre-existing ESLint Warnings**: 5 non-blocking warnings remain across `recon/page.tsx`, `setup/page.tsx`, and `ScreenshotGrid.tsx` for missing `alt` attributes or raw `<img>` tags.
2. **Unmounted Code**: `components/layout/AssistantPanel.tsx` remains in the repository but is unmounted from the layout.
3. **Severity Utility Classes**: Monitor and other pages use utility classes like `text-critical`, `bg-critical/15` which rely on CSS variables rather than the `severity-critical` naming defined in `tailwind.config.ts`.
4. **Mock Feed Simulation**: Connection delay and outage recovery are driven by React state and timers, without live backend telemetry.

## Follow-up Recommendations

1. Address pre-existing ESLint image warnings by switching to `next/image` in a targeted cleanup ticket.
2. Align token classes in `tailwind.config.ts` so `critical`/`high`/`medium`/`low` are directly accessible alongside `severity.*`.
3. Standardize authentication token storage (`localStorage.token` vs `access_token`) prior to connecting the Axum backend in future tickets.
