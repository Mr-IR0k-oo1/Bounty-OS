## Changes Made

### 1. ESLint configuration (non-interactive)

- `.eslintrc.json` **already existed and was tracked** (committed in HEAD: `{ "extends": "next/core-web-vitals" }`) — the prior audit's "missing" finding refers to older state.
- The real blocker was that **`eslint` and `eslint-config-next` were absent** from `package.json` and `node_modules`, so `next lint` could not resolve the config non-interactively.
- Added pin-compatible devDependencies so linting resolves deterministically:
  - `eslint@^8.57.0` (installed 8.57.1)
  - `eslint-config-next@14.1.0` (matches Next `14.1.0`)
- Toolchain: ESLint 8 + legacy `.eslintrc.json` — the correct pairing for Next 14.

### 2. `typecheck` script

- Added `"typecheck": "tsc --noEmit"` to `scripts` in `frontend/package.json`. All pre-existing scripts untouched.

### 3. Phantom package metadata (`"module": "src/index.ts"`)

- **Removed.** Decision:
  - The frontend is a Next.js application, not a publishable library; nothing imports the package by name, so the `module` (ESM entry) field is never consulted by the bundler or Node.
  - The pointed-to path `src/index.ts` does not exist (no `src/` directory; sources live under `app/`, `components/`, `lib/`).
  - Removal is safe and removes misleading metadata. `"type": "module"` was **kept**: it is load-bearing because `next.config.js` uses `export default` ESM syntax.

### 4. Monitor route

- `frontend/app/(app)/monitor/page.tsx` was **already committed in HEAD** (`9be9346 "ui update"`), so the sidebar `/monitor` link no longer 404s.
- Enhanced the existing page to fully meet the spec (still 100% mock, no API):
  - **Loading state:** simulated initial feed connection (`isConnecting`, clears after 900 ms) rendering skeleton cards + "Connecting to monitor feed…" (verified in SSR HTML output).
  - **Empty state:** the "All hosts quiet" card now renders via the conditional branch (also reachable via filters/search and Clear Logs).
  - **Error state:** `feedError` + error card with a Reconnect button; triggered by a small "Simulate feed outage" control (`WifiOff` icon) in the Live tab toolbar, labelled and aria-labelled as a simulation. Reconnect restores the stream.
  - **Responsive fix:** Host Watchlist table wrapped in `overflow-x-auto` so it scrolls rather than clipping on narrow viewports.
  - The page already covered: active monitors (KPI row), recent events (Change Feed), monitor status (Live Stream pill + status badges), severity (per-event badges), last activity (timestamps).
  - Explicitly **no** WebSocket/backend calls — the old no-op heartbeat interval was replaced by the connect simulation.

### 5. Project navigation review (minimal fixes)

- Enumerated every live `href` / `router.push` across pages and components against the 29-route inventory from the audit. All live links resolve.
- Single route mismatch found: `components/projects/ProjectCard.tsx` linked `href="/projects/${slug}/kanban"` to a route that does not exist. `ProjectCard` is currently **unused** (0 imports), so this was dead code, but the mismatched href was corrected to `/projects/${slug}` (the real project overview route) to prevent a future 404.
- Left the in-page project detail tabs (Overview/Programs/Kanban/Notes/Timeline/Team) vs. the dedicated subroutes alone — harmonizing them is a redesign, explicitly out of scope.

## Decisions

1. **ESLint approach:** kept the existing `.eslintrc.json` (`next/core-web-vitals`) and added the missing `eslint@8` + `eslint-config-next@14.1.0` devDeps rather than inventing a new config format (ESLint 9's `eslint.config.js` is incompatible with Next 14's `next lint`).
2. **`module` removed, `type` kept:** `module` pointed to a non-existent file and is meaningless for an application; `type: "module"` is required for the ESM `next.config.js`.
3. **Lint errors fixed (2), warnings left (6):** only the two blocking `react/no-unescaped-entities` errors in `findings/page.tsx` were fixed; image `alt`/`<img>` warnings are pre-existing, non-blocking, and out of scope.
4. **Monitor page enhanced, not rewritten:** the route already existed in HEAD; work was additive (loading/error states + responsive table) to satisfy the spec without a redesign.
5. **Kanban href:** single dead-link fix; no project-tab harmonization (that would be a redesign).
6. **AssistantPanel removed from layout only:** component file retained for reversibility; classified as a request-driven layout change, not a feature deletion.
7. **No backend work:** every change is structural/mock-only per the task's DO NOT list.
